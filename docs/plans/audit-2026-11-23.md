### 3. History M2: uploads history and per-user access (about 75 min)

- `pipeline/src/db/uploads.mjs`: `upsert(job, userId)` writing `uploads` and `upload_stages` in one transaction (`INSERT … ON CONFLICT DO UPDATE`), `list(userId, {before, limit})`, `get(id, userId)`. Admins read all.
- `pipeline/src/jobs.mjs` `createJobManager`: add an injected `onChange(job)` called on every snapshot change, throttled to state transitions and a coarse progress interval. Its failure is caught and logged, never failing the job.
- Owner: `handleUpload` in `server.mjs` already has the session user; store `userId` in `meta` so it survives in `work/jobs/<id>.json`. `GET /jobs`, `/jobs/:id` and `/events` filter on it (this closes the audit gap). Jobs with no owner (from before auth) belong to admin.
- Backfill existing `work/jobs/*.json` once at startup into `uploads`, owned by admin.
- New routes: `GET /uploads` (keyset `?before=`), `GET /uploads/:id` (includes the snapshot).
- Web: `web/src/history/{api,types}.ts`; Analysis page gets an Uploads table (name, status, duration, size, output id, link to open the result). The "Recent uploads" list on the upload page can switch to the same data later.
- Tests: repo round trip and upsert idempotence against the compose DB; user A cannot read user B's jobs (list, get, SSE); DB failure does not fail a job; backfill is idempotent; `history/` mappers.

### 4. History M3: save and list benchmark runs (about 60 min)

- `pipeline/src/db/benchmarks.mjs` and `artifacts.mjs`: `create({label, env, sessions, events})` writes run, sessions and a `telemetry-events` artifact in one transaction, with the 5 MB cap and downsampling of `sample` events recorded in the blob. `list`, `get`, `getArtifact`, `delete`.
- Routes: `POST /benchmarks`, `GET /benchmarks`, `GET /benchmarks/:id`, `GET /benchmarks/:id/artifacts/:kind`, `DELETE /benchmarks/:id`, all per user. The JSON body limit (4 KB in `readJson`) needs a larger per-route cap here.

No chart library yet.
- Tests: transactionality (a failed artifact write leaves no run), cap and downsample, ownership, cascade on delete, and a round trip from a built `TelemetryEvent[]` to the stored summary and back.
